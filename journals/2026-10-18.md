## What I learned

### Image vs container
An image defines packaged filesystem and configuration. A container is an instance created from an image, whose main process determines its active lifetime.

### Detached execution
`-d` runs without attaching the terminal; it does **not** guarantee that the main process keeps running. A shell-only image may exit when standard input closes, while Nginx can stay running because its server process stays alive.

### Networking and published ports
Container port 80 and host port 8080 are different endpoints. Publishing a port makes a listening service reachable at the configured host interface but does not start the service itself.

### Bind mounts
Nginx can serve a host directory through `/usr/share/nginx/html`. Changing host files can update responses without changing the image.

### Pods
Containers inside a Podman pod can share localhost networking. Shared files require an explicitly configured volume or bind mount; pod membership alone is not a filesystem volume.

### Image management
I practiced discovering an image in a registry, pulling tagged Ubuntu versions, inspecting image metadata and cleaning up the specific image used for the exercise.
