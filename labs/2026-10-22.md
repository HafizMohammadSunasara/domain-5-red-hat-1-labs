## Lab 01 — FROM: choosing a base image

**Objective:** Understand the first stage of an image build, why base image choice matters, and how tags and digests affect reproducibility.

**Observed from retained screenshots:**

- The Containerfile used `FROM registry.access.redhat.com/ubi8/ubi:8.7`.
- Podman successfully built and tagged `localhost/my-base-image:latest`.
- `podman images` showed the custom image and the Red Hat UBI 8.7 base image.
- Running the image to read `/tmp/status.txt` displayed `base image successfully set up` (as actually shown in the terminal).
- Build output included capability-related `operation not permitted` warnings; these did not prevent the shown build and readback from succeeding. They should not automatically be interpreted as harmless in other environments.

**What I learned:** `FROM` establishes the base filesystem and starting configuration. A version tag is more intentional than `latest`, but a digest is the stronger pin when identical image content must be enforced. The displayed `latest` on my *local custom image* is its tag and does not mean the Containerfile pulled a `latest` UBI base.

**Reproduce:** Follow the [lab runbook](../labs/topic-02-certified-specialist/lab-01-understanding-from-instruction/README.md) and inspect the [deep dive](../labs/topic-02-certified-specialist/lab-01-understanding-from-instruction/DEEP-DIVE.md).

## Lab 02 — RUN: shell/exec forms and layer optimization

**Objective:** Practice `RUN` forms and compare a multi-`RUN` package installation against a combined install-and-cleanup step.

### Observed image comparison

| Image | Shown size | Recorded Dockerfile RUN steps |
| --- | ---: | ---: |
| `localhost/run-lab-shell:latest` | 14.1 MB | 1 |
| `localhost/run-lab-exec:latest` | 14.1 MB | 1 |
| `localhost/inefficient-multi-layer:latest` | 160 MB | 3 |
| `localhost/optimized-nginx:latest` | 116 MB | 1 |

**Recorded difference:** 44 MB smaller for the optimized image, approximately **27.5%** relative to 160 MB. These are the sizes reported by Podman in this lab environment, not universal benchmark results.

**Observed in `podman history`:** The inefficient build had distinct `apt-get update`, `apt-get install -y nginx`, and cleanup instructions; the optimized build showed one combined command. This helps explain why deleting cache files in a later layer cannot necessarily remove bytes already captured in an earlier layer.

**Important qualification:** The measured reduction should not be attributed to the RUN count alone. Package selection, cache cleanup in the same layer, base image, and build configuration can change image size. A fully controlled comparison holds those factors constant.

## Lab 03 — ADD vs COPY: copying, extraction, downloads, and cache

**Objective:** Compare local file copying, archive extraction, remote URL behavior, and cache invalidation; review the risks of untrusted inputs.

**Six lab areas documented:**

1. `COPY` a local text file.
2. `ADD` the same text file and compare normal file-copy behavior.
3. Use `ADD` to unpack a local `.tar.gz` archive.
4. Examine `ADD` of an HTTPS-hosted file.
5. Change source content and observe build-cache implications for `COPY` and `ADD`.
6. Use a harmless simulated archive to discuss extraction/security boundaries.

**Evidence limitation:** I reported completing the practical lab but deleted the remote lab environment before saving the terminal screenshots. Only a screenshot of the LMS lesson interface was retained. The Dockerfiles and accompanying assets are study/reproduction materials; they are not archived proof that every command ran successfully.

**Key engineering takeaways:** Prefer `COPY` for ordinary build-context files. Use `ADD` intentionally for capabilities such as local tar extraction or supported remote sources. Avoid assuming a remote moving URL is immutable or that automatic archive extraction is safe for untrusted input. `RUN` happens during the image build, while a command executed with `podman run` is a separate runtime action.

**Reproduce and validate when revisiting:** [Lab runbook](../labs/topic-02-certified-specialist/lab-03-add-vs-copy/README.md) · [Deep dive](../labs/topic-02-certified-specialist/lab-03-add-vs-copy/DEEP-DIVE.md).
